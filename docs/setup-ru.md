# DashPad: установка с нуля

Инструкция для разработчика на Windows: как развернуть свой Cloudflare Worker, собрать приложение для планшета, превратить планшет в киоск и показать на нём свой «Ход работ».

Обозначения в командах:
- `<ваш-субдомен>` — поддомен вашего аккаунта на `workers.dev`;
- `<ключ-записи>` и `<ключ-чтения>` — ключи, которые вы создадите в шаге 3.4;
- `<имя>` — имя вашей учётной записи Windows.

Команды даны для PowerShell. Запускайте их из корня клона репозитория, если в шаге не сказано иное.

## 1. Что получится

Планшет на стене показывает одну страницу без кнопок и без входа в аккаунты.

- **Левая половина:** часы, дата, календарь на месяц, погода на сегодня и на 7 дней, воздушная тревога, график отключений света (ДТЭК).
- **Правая половина:** ваш «Ход работ» — те же цепочки задач, что в артефакте «Ход работ» ваших сессий Claude Code.

Части системы:

| Часть | Папка | Где работает |
|---|---|---|
| Worker (API, настройки, копия «Хода работ») | `worker/` | ваш аккаунт Cloudflare, бесплатный план |
| Страница дашборда | `dashboard/` | отдаёт тот же Worker |
| Приложение-киоск | `android/` | планшет |
| Публикатор «Хода работ» | `scripts/progress-publisher.py` | ваш ПК, задача планировщика Windows |

## 2. Что понадобится

ПК с Windows 10 или 11 и программы:
- git;
- Node.js 24 (с npm);
- Python 3 — нужна только стандартная библиотека;
- JDK 17 (например, Eclipse Temurin 17);
- Android SDK с platform-tools (`adb`). Проще всего поставить Android Studio и один раз открыть в ней папку `android\`: студия скачает SDK и запишет путь к нему.

Аккаунты и ключи:
- бесплатный аккаунт Cloudflare;
- по желанию — токен API alerts.in.ua (заявка на https://alerts.in.ua/api-request). Без токена тревоги приходят из публичного источника siren.pp.ua.

Планшет:
- Android с USB-кабелем к ПК;
- лучше всего — планшет, который больше ни для чего не нужен. Киоск-режиму нужен планшет **без аккаунтов** (см. шаг 7);
- экран около 10" с соотношением 16:10, в горизонтальной ориентации: вёрстка рассчитана на него. Проверено на SM-T505 (страница 1333×800 CSS-пикселей).

Проверьте, что всё на месте:

```powershell
git --version; node --version; python --version; adb version
```

Если `adb` не найден, добавьте папку `platform-tools` в `PATH` или поставьте её отдельно: `winget install Google.PlatformTools`. Скрипт `provision.ps1` найдёт `adb` и без `PATH`: он смотрит в пакет WinGet и в `%LOCALAPPDATA%\Android\Sdk\platform-tools`.

## 3. Cloudflare: развернуть Worker

> Команды `wrangler` этого раздела сверены с `--help` wrangler 4.165.0. На чистом аккаунте Cloudflare их не запускали: они создают ресурсы в аккаунте.

### 3.1. Клонировать репозиторий и поставить зависимости

```powershell
git clone https://github.com/innoxxicide/DashPad-public.git DashPad
cd DashPad
cd worker; npm ci; cd ..
cd dashboard; npm ci; cd ..
```

### 3.2. Собрать дашборд

Сначала соберите дашборд: Worker отдаёт готовую сборку из `dashboard\dist`. Без неё `wrangler deploy` не найдёт папку со статикой.

```powershell
cd dashboard; npm run build; cd ..
```

### 3.3. Войти в Cloudflare и развернуть Worker

```powershell
cd worker
npx wrangler login
npx wrangler deploy
```

- `npx wrangler login` открывает браузер для входа в Cloudflare.
- Если у аккаунта ещё нет поддомена `workers.dev`, wrangler попросит его выбрать (из документации, не запускали).
- База D1 `dashpad`: в `worker\wrangler.jsonc` у неё нет `database_id`. Wrangler 4.45 и новее при первом `deploy` сам создаёт базу и записывает её `database_id` в `wrangler.jsonc` (из документации, не запускали: [changelog Cloudflare](https://developers.cloudflare.com/changelog/2025-10-24-automatic-resource-provisioning/)).
- Если `deploy` всё же жалуется на базу, создайте её вручную:
  1. Выполните `npx wrangler d1 create dashpad`.
  2. Скопируйте из вывода значение `database_id`.
  3. В `worker\wrangler.jsonc` добавьте в блок `d1_databases` строку `"database_id": "<ID>"`.
  4. Повторите `npx wrangler deploy`.
- Таблицы в базе Worker создаёт сам при первом запросе. Миграции не нужны.
- `database_id` вашей базы попадает в `worker\wrangler.jsonc`, а этот файл отслеживает git. Закоммитьте эту правку в своём клоне: без коммита её легко потерять, а `git pull` откажется перезаписать изменённый файл.

В конце `deploy` печатает адрес Worker: `https://dashpad.<ваш-субдомен>.workers.dev`. Это адрес дашборда.

### 3.4. Создать ключи

Нужны два случайных ключа:
- **ключ записи** — им публикатор на ПК отправляет «Ход работ»;
- **ключ чтения** — им планшет и страница настроек читают данные.

Выполните команду два раза, по разу на каждый ключ:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Такой ключ состоит только из `A-Z a-z 0-9 - _`. Скрипт `provision.ps1` принимает только эти символы и ещё `. ~`.

### 3.5. Записать ключи в Worker

Из папки `worker\`:

```powershell
npx wrangler secret put PROGRESS_WRITE_KEY
npx wrangler secret put DASHPAD_READ_KEY
```

Каждая команда спрашивает значение: вставьте ключ записи и ключ чтения соответственно. Секреты не попадают ни в git, ни в `wrangler.jsonc`.

Если есть токен alerts.in.ua:

```powershell
npx wrangler secret put ALERTS_IN_UA_TOKEN
```

### 3.6. Проверить Worker

```powershell
curl.exe https://dashpad.<ваш-субдомен>.workers.dev/api/health
curl.exe -H "Authorization: Bearer <ключ-чтения>" https://dashpad.<ваш-субдомен>.workers.dev/api/health
```

- Первый ответ без ключа: `{"ok":true,"version":"…"}`.
- Второй ответ с ключом дополнительно содержит `alertsSource`, `feeds` и `publisherHeartbeatAgeSec`. Если этих полей нет, ключ чтения не совпал с секретом `DASHPAD_READ_KEY`.

Откройте в браузере ПК `https://dashpad.<ваш-субдомен>.workers.dev/?k=<ключ-чтения>`. Страница запомнит ключ в браузере. Левая половина должна заполниться данными.

Для локальной разработки (`npx wrangler dev --local`) скопируйте `worker\.dev.vars.example` в `worker\.dev.vars` и заполните его тестовыми ключами. Файл `.dev.vars` git не отслеживает.

## 4. Файл настроек ПК: publisher.json

Публикатор и скрипт подготовки планшета читают один файл: `%USERPROFILE%\.dashpad\publisher.json`. Он лежит вне репозитория.

1. Скопируйте пример:

   ```powershell
   New-Item -ItemType Directory -Force "$env:USERPROFILE\.dashpad" | Out-Null
   Copy-Item scripts\publisher.example.json "$env:USERPROFILE\.dashpad\publisher.json"
   notepad "$env:USERPROFILE\.dashpad\publisher.json"
   ```

2. Заполните поля:

   | Поле | Значение | Кто читает |
   |---|---|---|
   | `url` | `https://dashpad.<ваш-субдомен>.workers.dev` | публикатор, `provision.ps1` |
   | `writeKey` | ключ записи | публикатор |
   | `readKey` | ключ чтения | `provision.ps1` (передаёт его планшету) |
   | `transcripts` | папка транскриптов Claude Code, шаг 5 | публикатор |
   | `template` | файл шаблона страницы «Ход работ», шаг 5 | публикатор |

3. Пишите пути через `/` (`%USERPROFILE%/.claude/projects`) или удваивайте обратную косую черту (`C:\\Users\\<имя>\\.claude\\projects`). Одиночная `\` ломает JSON. Публикатор раскрывает в путях `%USERPROFILE%` и другие переменные среды.
4. Сохраните файл в Блокноте. Не пишите его командами PowerShell 5.1 `Set-Content` или `Out-File`: они могут испортить кириллицу в путях.

## 5. «Ход работ» на планшете

Ваши сессии Claude Code уже ведут артефакт «Ход работ». Публикатор читает транскрипты этих сессий на ПК (логи сессий, файлы `*.jsonl`), собирает из них цепочки и отправляет их в ваш Worker. Планшет показывает их справа. Вход в claude.ai на планшете не нужен.

Самый быстрый путь:

1. В `publisher.json` задайте два поля:
   - `transcripts` — папка, где Claude Code хранит транскрипты сессий. Обычно это `%USERPROFILE%/.claude/projects`.
   - `template` — файл шаблона страницы «Ход работ» из вашего рабочего репозитория, обычно `<рабочий репозиторий>/.claude/hooks/progress_page.html`.

   Пример:

   ```json
   {
     "url": "https://dashpad.<ваш-субдомен>.workers.dev",
     "writeKey": "<ключ-записи>",
     "readKey": "<ключ-чтения>",
     "transcripts": "%USERPROFILE%/.claude/projects",
     "template": "D:/work/<рабочий репозиторий>/.claude/hooks/progress_page.html"
   }
   ```
2. Проверьте, что публикатор видит оба пути:

   ```powershell
   python -I scripts\progress-publisher.py status
   ```

   В выводе ищите строку `transcripts: <путь> (found)`, число цепочек `mirror: N chains (M open)` и размер шаблона `template: N bytes`. Слово `missing` значит, что путь неверный.
3. Отправьте данные один раз:

   ```powershell
   python -I scripts\progress-publisher.py once
   ```

4. Откройте `https://dashpad.<ваш-субдомен>.workers.dev/progress?k=<ключ-чтения>` в браузере ПК. Там должны быть ваши цепочки.
5. Включите постоянную публикацию:

   ```powershell
   python -I scripts\progress-publisher.py install
   ```

   Команда создаёт задачу планировщика «DashPad progress publisher». Задача стартует каждые 5 минут; вторая копия сразу завершается. Работающая копия проверяет транскрипты каждые 10 секунд и отправляет изменения не чаще раза в 10 секунд. Удалить задачу: `python -I scripts\progress-publisher.py uninstall`.

Что важно знать:
- Первый запуск читает только транскрипты за последние 35 дней. Дальше публикатор помнит, где остановился.
- Если файл состояния `progress\progress_state.json` в папке настроек удалён или потерян, публикатор снова читает только последние 35 дней. Цепочка, начатая раньше, пропадёт и вернётся, только когда её документ снова запишут целиком. Частичные правки такой цепочки (обновление полей, замена текста) публикатор пропускает.
- Если транскриптов много, первое чтение занимает несколько минут: первый `once` или `run`, а также `status` до них. Потом `status` продолжает с сохранённого места и отвечает за секунды. Предупреждение `N file_path writes skipped: the file changed after the write` при первом чтении — норма: более поздние записи той же цепочки заменяют пропущенные.
- Публикатор видит только сессии этого ПК и только одну папку `transcripts`.
- Журнал публикатора: `%USERPROFILE%\.dashpad\publisher.log`.
- Файл настроек в другом месте: добавьте `--config <путь к publisher.json>` к любой команде публикатора. `install` передаёт этот путь задаче планировщика. Журнал и состояние публикатора тогда лежат в папке этого файла. `provision.ps1` такого ключа не знает и всегда читает `%USERPROFILE%\.dashpad\publisher.json`.
- Открытые цепочки без обновлений дольше порога (по умолчанию 72 часа) сворачиваются в одну строку внизу. Порог меняется на странице настроек (шаг 9).

**Стендап-бриф.** Если ваш навык брифа пишет `standup_brief.html` вместе с `standup_brief.json` в папку сессии Claude Code (`%TEMP%\claude\…\scratchpad\`), публикатор сам находит самый новый бриф и отправляет его. Настраивать ничего не нужно.

## 6. Собрать приложение (APK)

```powershell
$env:JAVA_HOME = (Get-Item 'C:\Program Files\Eclipse Adoptium\jdk-17*' | Select-Object -Last 1).FullName
cd android
.\gradlew.bat assembleDebug
cd ..
```

- Путь к JDK замените на свой, если JDK 17 стоит в другой папке.
- Gradle сообщает `BUILD SUCCESSFUL`, а APK появляется в `android\app\build\outputs\apk\debug\app-debug.apk`.
- Это debug-сборка с тестовой пометкой (`testOnly`). Поэтому каждая установка — только `adb install -r -t`.

> 🔴 **Сохраните ключ подписи.** Первая сборка создаёт ключ `%USERPROFILE%\.android\debug.keystore`. Сделайте его копию вне git. Приложение в режиме Device Owner обновляется только APK с той же подписью. APK, собранный с другим ключом (другой ПК, новый ключ), не встанет поверх. А удаление DashPad снимает режим Device Owner, и киоск придётся настраивать заново.

## 7. Подготовить планшет

Киоск строится на режиме Device Owner. Android разрешает его назначить через `adb`, только когда на планшете **нет ни одного аккаунта** (Google, Samsung и любых других) и есть **ровно один пользователь**.

1. Подключите планшет к Wi-Fi: «Настройки» → «Wi-Fi». Без сети дашборд не получит данные.
2. Включите режим разработчика: «Настройки» → «О планшете» → 7 раз нажмите «Номер сборки».
3. В «Настройки» → «Для разработчиков» включите «Отладка по USB».
4. Подключите планшет к ПК. На планшете разрешите отладку для этого ПК.
5. Проверьте связь: `adb devices` показывает одно устройство со статусом `device`.
6. Удалите все аккаунты: «Настройки» → «Аккаунты». Удалите также дополнительных пользователей и гостевые профили.
7. Проверьте, готов ли планшет:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts\provision.ps1 -PreCheckOnly
   ```

   Строка `1 set-device-owner: READY` значит, что можно продолжать (шаг 8). Строка `BLOCKED (…)` перечисляет причины. Эта команда ничего не меняет на планшете.

Если аккаунт не удаляется (родительский контроль, корпоративный профиль, системный аккаунт производителя), остаётся только сброс к заводским настройкам.

> 🔴 **Сброс к заводским настройкам стирает с планшета ВСЕ данные: аккаунты, приложения, фото, файлы. Вернуть их нельзя.** Перед сбросом сохраните всё нужное. После сброса пропустите вход в Google при первом запуске и не добавляйте аккаунты, затем повторите пункты 1–7.

Сменить сеть Wi-Fi позже, в режиме киоска: ⚙ → «Змінити мережу →». Поверх киоска откроется системная панель Wi-Fi.

Проверенный пример: Samsung Galaxy Tab A7 (SM-T505) с LineageOS. Прошивка ставится по [docs/lineageos-install.md](lineageos-install.md) (инструкция на украинском). На этой прошивке нет сервисов Google, поэтому аккаунтов нет с самого начала. Другие планшеты подойдут, если на них ставится Device Owner через `adb`; на них инструкцию не проверяли.

## 8. Превратить планшет в киоск: provision.ps1

Скрипт `scripts\provision.ps1` работает по USB через `adb`. Каждый шаг сначала читает состояние и меняет его, только когда нужно. Повторный запуск безопасен.

Все запуски имеют вид:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\provision.ps1 <ключ>
```

| Ключ | Что делает |
|---|---|
| `-PreCheckOnly` | только читает и показывает состояние: пользователи, аккаунты, владелец, версия APK, HOME, режим Lock Task |
| без ключа | ставит APK, если его нет, и выдаёт приложению нужные разрешения |
| `-Install` | переустанавливает APK всегда |
| `-Configure` | передаёт планшету адрес дашборда (`url` и `readKey` из `publisher.json`) и сервисный PIN. PIN спрашивается скрыто, минимум 4 цифры |
| `-SetDeviceOwner -ConfirmDeviceOwner com.dashpad/.AdminReceiver` | назначает DashPad владельцем устройства и проверяет киоск. Отказывает, если есть аккаунты, больше одного пользователя или другой владелец |
| `-DisableLauncher3` | отключает стандартный лаунчер `com.android.launcher3`. Только после того, как DashPad стал владельцем и HOME |

Порядок для нового планшета:
1. `-PreCheckOnly` — убедитесь, что `set-device-owner: READY`.
2. Запуск без ключа — установка APK и разрешения.
3. `-Configure` — адрес дашборда и PIN. На планшете появится дашборд.
4. `-SetDeviceOwner -ConfirmDeviceOwner com.dashpad/.AdminReceiver` — режим киоска.
5. Перезагрузите планшет: `adb reboot`. Дашборд должен появиться сам, без касаний.
6. Только на LineageOS и других прошивках с лаунчером `com.android.launcher3`: запустите `-DisableLauncher3` отдельным запуском. Скрипт не выполняет его вместе с `-SetDeviceOwner`.
7. Перезагрузите планшет ещё раз.

Сервисный PIN открывает на планшете меню ⚙ → «Сервіс…». Запомните его.

Ключ `-Pin <цифры>` вместе с `-Configure` — только для тестового PIN: значение остаётся в истории PowerShell.

## 9. Настройки дашборда

Страница настроек открывается двумя способами:
- на планшете: ⚙ → «Налаштування дашборда»;
- на ПК: `https://dashpad.<ваш-субдомен>.workers.dev/?k=<ключ-чтения>#settings`.

| Раздел | Что задать | По умолчанию |
|---|---|---|
| «Погода» | населённый пункт | Київ |
| «Повітряна тривога» | область, район и громада | Київська область |
| «Графік відключень» | регион ДТЭК, очередь, при желании адрес | Київська область (ДТЕК КРЕМ) |
| «Екран» | яскравость днём и ночью, часы ночи, порог заряда | 70 % / 10 %, 23:00–07:00, 30 % |
| «Ход работ» | через сколько часов сворачивать неактивные цепочки | 72 |

Регионы графика отключений: Київська область, Київ, Дніпропетровська область, Одеська область.

Новый планшет начинает с настроек по умолчанию: погода для Киева, тревога и график отключений для Киевской области. Сначала задайте на странице настроек своё место.

## 10. Как выйти из киоска

Порядок важен: снять владельца → включить лаунчер → только потом, если нужно, удалить DashPad.

1. Снимите владельца. На планшете: ⚙ → «Сервіс…» → PIN → «Зняти режим кіоску (Device Owner)». Или с ПК:

   ```powershell
   adb shell dpm remove-active-admin com.dashpad/.AdminReceiver
   ```

   Команда работает только благодаря тестовой пометке APK (шаг 6). После снятия экран блокировки остаётся выключенным. Включить его: `adb shell locksettings set-disabled false`.
2. Если лаунчер отключали (шаг 8, пункт 6), включите его: `adb shell pm enable com.android.launcher3`. Иначе после удаления DashPad на планшете не останется главного экрана.
3. Только после пунктов 1 и 2 удалите DashPad, если нужно: `adb uninstall com.dashpad`.
4. Сброс к заводским настройкам — крайняя мера: из настроек Android или из режима восстановления (recovery). Он стирает все данные.

Пункт «Вийти з режиму кіоску й відкрити налаштування Android» в меню «Сервіс…» выходит из киоска временно и открывает настройки Android. DashPad остаётся владельцем.

`adb shell am task lock stop` киоск Device Owner **не снимает**: режим остаётся `LOCKED` (измерено на SM-T505). Это не выход.

Ожидается по коду Android, не измерено:
- снятие владельца при включённом киоске один раз закрывает задачу DashPad — дашборд перезагружается;
- снятие владельца после выхода через «Сервіс…» может оставить строку состояния скрытой до перезагрузки.

После снятия Device Owner на планшете остаются:
- `stay_on_while_plugged_in` = 7 (экран не гаснет на зарядке);
- тайм-аут экрана 30 минут;
- включённая геолокация и разрешение DashPad на точную геолокацию (уже не закреплённое).

Запрет безопасного режима, который ставил владелец, система снимает сама.

## 11. Обновление

**Worker и дашборд:**

```powershell
cd dashboard; npm run build; cd ..
cd worker; npx wrangler deploy; cd ..
```

Страница на планшете сама замечает новую сборку и перезагружается.

**Приложение на планшете:**
1. Соберите APK (шаг 6) на ПК с тем же ключом подписи.
2. Установите его: `adb install -r -t android\app\build\outputs\apk\debug\app-debug.apk`. Или `provision.ps1 -Install`.

В режиме киоска дашборд возвращается на экран сам примерно через 10–15 секунд.

**Новые версии кода.** Публичный репозиторий в архиве: новые версии в нём появляются только по запросу автора. Когда вы забираете новую версию в свой клон (`git pull`), сохраните свой коммит с `database_id` (шаг 3.3). Затем повторите сборку и `deploy` выше.

**Публикатор:** задача планировщика запускает скрипт прямо из клона. Новая версия скрипта заработает при следующем старте задачи.

## 12. Неполадки

| Признак | Что проверить |
|---|---|
| «Ход работ» застыл и показывает «ПК не на зв'язку», хотя публикатор работает; в журнале `HTTP Error 413` | набор цепочек перерос лимит Worker (бывает через годы работы). Остановите задачу (`uninstall`), удалите `progress_state.json` и `chains.js` в `%USERPROFILE%\.dashpad\progress\`, затем снова `install` |
| `403` или `forbidden` | ключ не совпадает с секретом. Ключ чтения — для планшета и страницы, ключ записи — для публикатора. Перезапишите секрет: `npx wrangler secret put <ИМЯ>` |
| На планшете «DashPad не налаштовано» | адрес не передан: `provision.ps1 -Configure` |
| «Ход работ» пустой | `python -I scripts\progress-publisher.py status`: нужны строки `transcripts: … (found)` и `template: N bytes`, а не `template: missing`. Затем журнал `%USERPROFILE%\.dashpad\publisher.log` |
| «Ход работ» не обновляется | работает ли задача планировщика «DashPad progress publisher»; возраст последнего сигнала публикатора — `publisherHeartbeatAgeSec` в `/api/health` с ключом чтения (шаг 3.6) |
| Нет блока отключений или ошибка в нём | регион и очередь в настройках (шаг 9). Если сайт ДТЭК недоступен, Worker берёт данные из svitlo.live |
| Старые данные на левой половине | меню ⚙ показывает возраст каждого источника. Возраст растёт — проверьте Wi-Fi планшета |
| `adb devices` показывает `unauthorized` | подтвердите запрос отладки на планшете; при необходимости `adb kill-server` и подключите кабель заново |
| `set-device-owner: BLOCKED` | причина указана в скобках: уберите аккаунты или лишних пользователей (шаг 7) |
| `SDK location not found` при сборке APK | файла `android\local.properties` нет в git. Перед `gradlew.bat` задайте `$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"` (путь SDK по умолчанию) или один раз откройте `android\` в Android Studio |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` при обновлении APK | APK подписан другим ключом: верните сохранённый `debug.keystore` и пересоберите (шаг 6) |
